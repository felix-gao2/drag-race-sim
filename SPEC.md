# Drag Race Simulator — SPEC.md

## Overview

Web app for comparing two real-world cars in a 1/4 mile drag race. User picks Car A and Car B via cascading dropdowns (Make → Model → Year → Trim), hits Start Race, then watches a side-by-side animation with a drag-racing Christmas tree countdown. After the race, a results screen shows winner, margin, and a synchronized speed-vs-time chart. Every race gets a shareable URL with an auto-generated OG preview image.

Differentiator from Motor Matchup: not adding features on top of theirs (mods, tunes, environmental conditions). Instead, reframing as a clean, focused 1v1 comparison tool with shareable links and telemetry visualization.

## Data Model

**`cars` table**
```
id              INTEGER PRIMARY KEY
make            TEXT NOT NULL
model           TEXT NOT NULL
year            INTEGER NOT NULL
trim            TEXT NOT NULL
horsepower      INTEGER NOT NULL
torque          INTEGER NOT NULL
weight_lbs      INTEGER NOT NULL
drivetrain      TEXT NOT NULL          -- 'FWD' | 'RWD' | 'AWD' | '4WD'
zero_to_sixty   REAL NOT NULL          -- seconds
quarter_mile    REAL NOT NULL          -- seconds
trap_mph        REAL                   -- nullable; finish-line mph
UNIQUE(make, model, year, trim)
```

**`races` table** (for shareable URLs)
```
slug            TEXT PRIMARY KEY       -- '2024-ford-mustang-gt-vs-2024-honda-civic-si'
car_a_id        INTEGER NOT NULL REFERENCES cars(id)
car_b_id        INTEGER NOT NULL REFERENCES cars(id)
created_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP
```

Slug generated by sorting the two car identifiers alphabetically, so A-vs-B and B-vs-A always resolve to the same URL.

## Data Seed

Curated CSV at `/backend/data/cars.csv` with columns matching the `cars` schema. Start with ~150 cars; can scale up. Seed script reads the CSV on first boot and upserts into SQLite.

Sources: publicly available drag-time databases (DragTimes, fastestlaps, manufacturer pages, magazine tests). Any car missing trap speed leaves that field NULL.

## API Endpoints

```
GET  /api/makes                              -> [{make}]
GET  /api/models?make=X                      -> [{model}]
GET  /api/years?make=X&model=Y               -> [{year}]
GET  /api/trims?make=X&model=Y&year=Z        -> [{trim}]
GET  /api/cars/:id                           -> full car object
POST /api/races                              -> body: {car_a_id, car_b_id}; returns {slug}
GET  /api/races/:slug                        -> {car_a, car_b, telemetry, winner, margin_sec}
GET  /api/og/:slug.png                       -> auto-generated OG image (1200x630)
```

`POST /api/races` is idempotent — same car pair returns the same slug. Telemetry is computed on the fly from each car's published times; no need to persist per-race telemetry data.

## Simulation Model

Each car has `zero_to_sixty` and `quarter_mile` times (plus optional `trap_mph`). Fit a speed-vs-time curve passing through these points.

Recommended model:
```
v(t) = v_term * (1 - exp(-k * t))
x(t) = v_term * (t + (exp(-k*t) - 1) / k)
```

Two unknowns (`v_term`, `k`), two constraints (v at 0-60 time = 60 mph, x at quarter-mile time = 1320 ft). Solve numerically (Newton-Raphson or bisection — Go's `math` package is enough).

If `trap_mph` is available, use a three-parameter model (e.g. add a linear term, or use a hyperbolic approach `v(t) = a*t / (1 + b*t) + c*t`). Phase 1 can ignore trap speed and start with the two-parameter exponential.

Generate telemetry as `[{time_s, speed_a_mph, speed_b_mph, dist_a_ft, dist_b_ft}, ...]` at 50ms intervals from t=0 until both cars cross 1320 ft. Winner = whichever crossed first. Margin = difference in finish times.

## Routes and Pages

### Landing — `/`

- Dark theme
- Hero section with a looping animation: a car driving across the screen (left to right), repeats
- Site title + one-sentence description
- "Get Started" CTA → navigates to `/race`

### Race Setup — `/race`

- Dark drag-strip themed background (asphalt, lane lines, sky gradient)
- Top bar: pill chips showing fixed race settings — `Distance: ¼ mile`, `Start: dig`. Display-only.
- Two car panels side by side: Car A (left), Car B (right)

**Each car panel:**
- When empty: 2×2 grid of cascading dropdowns
  - Top-left: **Make** — always enabled
  - Top-right: **Model** — enabled after Make is selected, filtered to that make
  - Bottom-left: **Year** — enabled after Model, filtered to available years for that model
  - Bottom-right: **Trim** — enabled after Year, filtered to trims for that year
- Changing any earlier dropdown resets the dropdowns after it
- Once all four are picked, the panel transitions to show the car's stats:
  - Header: `{year} {make} {model} {trim}`
  - 2×2 stats grid: Horsepower, Torque, Weight + Power:Weight, Drivetrain
  - Below: 0-60 time, 1/4 mile time (and trap mph if available)
  - "Remove" button to clear and re-select

- "Start Race" button — disabled until both panels are filled. On click:
  - `POST /api/races` with `{car_a_id, car_b_id}`
  - Receive `{slug}` in response
  - Navigate to `/race/:slug`

### Race View — `/race/:slug`

Reachable via Start Race or a shared link. Fetches `/api/races/:slug` on mount.

**Sequence:**

**1. Christmas tree countdown** (drag-racing accurate)
- Stage lights at the top of the tree light up (both cars "ready")
- Three amber bulbs drop in sequence, ~0.5s apart
- Green light = GO; cars launch on green
- Optional engine-rev audio during countdown

**2. Race animation** — side-by-side, stacked vertically
- Top lane: Car A (side-view, facing right)
- Bottom lane: Car B (side-view, facing right)
- Vertical starting line at the left edge of the strip; vertical finish line at the right edge
- Background (asphalt + lane markings) scrolls to convey speed
- Cars hold roughly center-screen but shift relative to each other to show the gap
- Live HUD per lane: current speed (mph), distance (ft), elapsed time (s)
- When a car crosses the finish line: its lane gets a winner highlight + "FINISHED" indicator

**3. Results panel** (appears after the race finishes)
- Winner badge: `{year} {make} {model} wins by 0.4s` (or "Dead heat" if margin < 0.05s)
- Side-by-side stats card: 0-60, 1/4 mile, trap speed (both cars; "—" if missing)
- Speed-vs-time chart (Recharts):
  - X-axis: time (s)
  - Y-axis: speed (mph)
  - Two overlaid lines, distinct colors, legend
  - Scrubber/playhead under the chart — dragging it replays the animation at that timestamp
- "Race Again" button → back to `/race`
- "Share" button → copies the current URL to clipboard, shows a toast

## Shareable URLs and OG Images

**Slug format:** `{yearA}-{makeA}-{modelA}-{trimA}-vs-{yearB}-{makeB}-{modelB}-{trimB}`, lowercased with hyphens, two cars sorted alphabetically so the order is deterministic.

**OG image** (`GET /api/og/:slug.png`):
- 1200×630 px
- Dark gradient background with brand accent colors
- Both car names (large), both 1/4 mile times, winner indicator
- No car photos in Phase 1 — pure typography
- Generated on first request, cached on disk by slug

**Meta tags** on `/race/:slug` (rendered server-side or via static head injection):
- `og:title`, `og:description`, `og:image` pointing to `/api/og/:slug.png`
- `twitter:card` = `summary_large_image`
